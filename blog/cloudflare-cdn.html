用 Cloudflare 免费加速 GitHub Pages

2026-08-15 · 预计阅读 6 分钟 · 作者：Azi36 · 前置阅读：在 GitHub 上免费部署静态网站

GitHub Pages 部署省心，但服务器在境外，国内访问时快时慢， 有时甚至打不开。解决办法也是免费的：把域名解析托管到 Cloudflare，套一层它的全球 CDN——访客会就近访问缓存节点， 而不是每次都跨洋去 GitHub 取文件。

原理一句话

没有 CDN 时：访客 → GitHub 服务器（境外），路远且挤。
有了 CDN 后：访客 → 就近的 Cloudflare 节点（缓存副本）， 只有缓存过期时 Cloudflare 才回 GitHub 取一次新文件。 对静态网站来说命中率极高，效果立竿见影。

第一步：注册 Cloudflare 并添加站点

  1. 注册 Cloudflare 账号
  2. 点 Add a site，输入你的域名（比如 azi36.com）
  3. 套餐选最下面的 Free（免费）——个人网站完全够用， 流量不限量

Cloudflare 会自动扫描你现有的 DNS 记录（之前配的 A 记录和 CNAME 都会被识别出来），确认无误即可。

第二步：把域名的 NS 改成 Cloudflare 的

添加完站点，Cloudflare 会分配给你两个 NS（域名服务器）地址， 长这样：

类型值（以你面板上显示的为准）
NSxxx.ns.cloudflare.com
NSyyy.ns.cloudflare.com

回到你购买域名的注册商后台，找到"DNS 服务器 / NS 设置"， 把默认的两条换成 Cloudflare 给的这两条。生效需要几分钟到 24 小时， 生效后 Cloudflare 面板会显示 Active。

注意：换 NS 之后，DNS 记录就全部在 Cloudflare 面板里管理了， 注册商那边原来的解析设置不再生效。

第三步：打开橙色云朵（关键）

在 Cloudflare 的 DNS 面板确认这几条记录存在， 并把 Proxy status 切换成 Proxied（橙色云朵）—— 这就是"套 CDN"的开关：

灰色云朵（DNS only）表示只解析不加速；橙色才会走 CDN。 四条 A 记录和 www 的 CNAME 都点亮。

第四步：SSL/TLS 选 Full（严格）

进入 SSL/TLS → Overview，加密模式选 Full (strict)。这一步很重要：

  • 选 Flexible 会和 GitHub 的强制 HTTPS 打架， 造成"重定向次数过多"的死循环——很多人翻车在这里
  • GitHub Pages 自带合法证书，所以放心选最严格的 Full (strict)

第五步：顺手开几个免费优化

  • SSL/TLS → Edge Certificates → Always Use HTTPS： 所有 http 访问自动跳转 https
  • Speed → Optimization：Brotli 压缩默认开启，确认即可
  • Caching → Configuration：Browser Cache TTL 按默认即可；改版后如果看到旧页面，来这里点 Purge Everything 清一次缓存

验证是否生效

等 NS 生效后，随便找个终端执行：

curl -I https://你的域名.com

# 响应头里看到这行就说明成功了：
server: cloudflare

响应头里还有个 cf-cache-status：HIT 表示这次访问命中了节点缓存，根本没去 GitHub——这就是加速的来源。

注意事项

  • DNS 记录本身不用改——还是指向 GitHub 的那 4 个 IP， 只是"管理的地方"从注册商搬到了 Cloudflare
  • GitHub 仓库里的 CNAME 文件和 Pages 设置保持原样
  • 之前做过的 TXT 域名验证记录也一并保留在 Cloudflare 里
  • 免费版完全够个人网站用，不需要买任何付费功能
部署在 GitHub，加速靠 Cloudflare，域名一年几十块—— 一个全球可访问的个人网站，成本基本就是一杯奶茶。
